# Generator expressions in CMake 4.1.0

Use `parse` when recording an expression and `evaluate` when the generator
knows the configuration, head target, current target and language. Set
`evaluate_for_buildsystem` when generating build rules. The context collects
target dependencies and sensitivity flags for callers that need them. Supply a
`DagChecker` root when evaluating sources, link libraries or another property
whose identity affects expression semantics. Create a fresh root per property
evaluation traversal.

`GenexError::to_string()` returns the diagnostic body. The caller supplies the
CMake message kind and resolves `backtrace` through its own backtrace table.
Issue the entries in `loop_steps` separately, and suppress error diagnostics
when `quiet` is set. An empty `expression` identifies a generator diagnostic
with a body of its own. The caller also delivers `EvalContext::warnings`.

Use `target_usage` with `INCLUDE_DIRECTORIES`, `COMPILE_DEFINITIONS`,
`COMPILE_OPTIONS`, `COMPILE_FEATURES`, `LINK_OPTIONS`, and `LINK_DIRECTORIES`.
It also accepts their `INTERFACE_` counterparts. Use `usage_requirements`
when the caller needs the context outputs or is generating device link rules.
The first occurrence of each input entry determines deduplication order and
provenance. A transitive item's `link_item` and `backtrace` are those of the
direct link that supplied the value, following `cmEvaluatedTargetProperty`.
Link options already have their `LINKER:` flags wrapped, and include items carry
their system classification. The generator determines the order of system and
ordinary include flags in the final command.

`GenexHost::property_entries` should return the original property entries
with their provenance. `target_property_raw` should return CMake's raw
`GetProperty` value, including generated properties such as `TYPE`, alias
semantics as applicable, and C++ module file-set properties. CMake 4.1.0 handles
`CXX_MODULE_SETS`, `CXX_MODULE_SET_*` and related names as target properties.
Its general node table has no `CXX_MODULES` expression. Use
`evaluate_custom_command` for the corresponding command/output configurations
and cross-config dependencies. Use `strip` for `string(GENEX_STRIP)` and
`preprocess` for export interface handling.

## Integration and remaining differences

- The integration host computes artifact names, imported configuration mapping,
  compiler standard availability, and runtime DLL locations. It also supplies
  scalar `COMPATIBLE_INTERFACE_*` property values and diagnostics. The default
  host hooks for these require only the information documented on each method.
- Raw link traversal handles direct additions and exclusions, imported
  `IMPORTED_LINK_INTERFACE_LIBRARIES[_<CONFIG>]`, and compile/link filtering.
  The target generator must supply resolved links for directory-scoped
  `::@` items, synthetic targets, and the second linker-language pass. The
  raw traversal uses the initial link language from `HAS_CXX` or
  `LINKER_LANGUAGE`. It does not cache link interfaces across calls.
- Usage collection includes ISPC implicit header directories and supports
  runtime usage supplied by the host. Swift module directories and Apple
  framework include injection are outstanding. Linux path behavior has oracle
  coverage. Windows native path and shell behavior, Apple bundle naming, PDB
  paths, and DLL runtime discovery need platform integration tests. The
  Unix-slash conversion expands bare `~` and `~/` from the environment and
  leaves named-user tildes as written.
- The evaluator returns a single fatal error with any DAG loop steps. The
  project generator controls when it emits diagnostics across configurations,
  languages, and repeated evaluations. Rust string outputs represent UTF-8,
  with replacement characters if a byte-oriented operation cuts a code point.

The captured corpora can be regenerated by running the scripts in
`tests/data` with the pinned oracle executable as their sole argument.
`genex_corpus.json` runs individual file(GENERATE) expressions in minimal
projects. `genex_usage_corpus.json` verifies generator usage order, backtrace
lines, shell expansion, linker wrappers and system include flags from the
oracle's diagnostics and generated Ninja files.
